# Day 06 - GitHub Workflow Concepts

## What Is GitHub Workflow?

GitHub Workflow is a collaboration process where developers create branches, make changes, submit Pull Requests, and merge approved code.

## Standard Workflow

Clone Repository

↓

Create Branch

↓

Develop Feature

↓

Commit Changes

↓

Push Changes

↓

Create Pull Request

↓

Review

↓

Merge

## What Is A Pull Request?

A Pull Request (PR) is a request to merge code from one branch into another.

Example:

feature-login

↓

main

## Why Pull Requests Are Important?

Benefits:

- Code Review

- Validation

- Quality Control

- Team Collaboration

## What Is Code Review?

Reviewing code before merging.

Goals:

- Detect Bugs

- Improve Quality

- Follow Standards

## What Is A Fork?

A fork creates a personal copy of a repository.

Used in:

- Open Source Projects

- External Contributions

## Clone vs Fork

Clone:

Copies repository locally.

Fork:

Creates repository copy in GitHub account.

## Branch Protection Rules

Protect important branches:

- main

- master

- production

Common rules:

- Require Pull Requests

- Require Reviews

- Restrict Force Push
