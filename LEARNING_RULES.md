# DevOps Learning Hub - Learning Rules

## Purpose

This document defines the standards and conventions followed throughout this repository.

The goal is to maintain consistency, readability, quality, and professionalism across all topics.

---

## Rule 1 - Standard Folder Structure

Every topic must follow the same structure.

Example:

Day01_Linux_Introduction

- README.md
- concepts.md
- commands.md
- lab_notes.md
- troubleshooting.md
- interview_questions.md
- summary.md
- screenshots/

---

## Rule 2 - README.md

Must contain:

- Topic Overview
- Learning Objectives
- Prerequisites
- Expected Outcomes
- Real-World Use Cases

---

## Rule 3 - concepts.md

Must contain:

- Definitions
- Theory
- Architecture
- Internal Working
- Real-World Examples

---

## Rule 4 - commands.md

Must contain:

- Command
- Syntax
- Description
- Example
- Expected Output

All commands must be tested before documenting.

---

## Rule 5 - lab_notes.md

Must contain:

- Objective
- Step-by-Step Lab
- Commands Executed
- Results Obtained
- Lessons Learned

---

## Rule 6 - troubleshooting.md

Must contain:

- Error Message
- Root Cause
- Resolution
- Prevention Strategy
- Best Practices

---

## Rule 7 - interview_questions.md

Must contain:

### Basic Questions

Questions suitable for beginners.

### Intermediate Questions

Questions commonly asked during interviews.

### Advanced Questions

Scenario-based and troubleshooting questions.

### Answers

Every question must have a complete answer.

---

## Rule 8 - summary.md

Must contain:

- Key Concepts
- Important Commands
- Frequently Used Commands
- Quick Revision Notes
- Cheat Sheet

---

## Rule 9 - Screenshots

Store all screenshots in:

- screenshots/

Naming Convention:

- ec2_creation.png
- docker_build_success.png
- terraform_apply_output.png

Use meaningful names.

---

## Rule 10 - Commit Strategy

Always use meaningful commit messages.

Examples:

- Add Linux Day01 Notes
- Complete Bash Day03 Conditions
- Add AWS IAM Lab Notes
- Add Docker Day02 Commands

Avoid messages such as:

- update
- latest changes
- work done
- test

---

## Rule 11 - Branch Strategy

### main

- Stable
- Reviewed
- Production Ready
- Well Structured

### devops

- Daily Learning
- Hands-On Labs
- Notes
- Experiments
- Draft Work

Merge into main only after validation.

---

## Rule 12 - Documentation First

Every topic must contain:

- Concepts
- Commands
- Labs
- Troubleshooting
- Interview Questions
- Summary

before marking the topic complete.

---

## Rule 13 - Repository Goal

A complete beginner should be able to:

- Learn DevOps
- Practice DevOps
- Revise DevOps
- Prepare for Interviews
- Build Projects

using this repository alone.

---

## Rule 14 - Naming Standards

Technology Folders:

- 01_LINUX
- 02_BASH
- 03_GIT
- 04_AWS

Day Folders:

- Day01_Linux_Introduction
- Day02_File_System
- Day03_File_Management

Follow a consistent naming convention throughout the repository.

---

## Rule 15 - Learning Philosophy

Learn in the following order:

1. Concepts
2. Commands
3. Hands-On Practice
4. Troubleshooting
5. Interview Questions
6. Summary Notes
7. Real Projects

Practice is mandatory.

Documentation is mandatory.

Consistency is mandatory.
