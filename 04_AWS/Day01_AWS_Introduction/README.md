# Day 01 - AWS Introduction

## Overview

This module introduces cloud computing, Amazon Web Services, cloud service models, deployment models, AWS Global Infrastructure, Regions, Availability Zones, Points of Presence, service scope, the AWS Shared Responsibility Model, and basic AWS account navigation.

An AWS Region is a separate geographic area. Availability Zones are isolated locations within a Region and are connected using low-latency, high-bandwidth, highly redundant networking. AWS recommends deploying applications across multiple Availability Zones when high availability is required.

## Learning Objectives

By the end of this module, you should be able to:

- Explain cloud computing in simple terms

- Explain why organizations adopt cloud services

- Differentiate IaaS, PaaS, and SaaS

- Differentiate public, private, hybrid, and multi-cloud approaches

- Explain AWS Regions and Availability Zones

- Understand the purpose of edge infrastructure

- Differentiate Regional, Availability Zone, and global service scope

- Explain high availability and fault tolerance

- Explain the AWS Shared Responsibility Model

- Navigate the AWS Management Console safely

- Identify the currently selected AWS Region

- Understand the difference between the AWS account root user and IAM identities

- Apply basic AWS cost-safety practices

## Cost Safety Notice

This introductory module does not require launching paid infrastructure.

Before creating any AWS resource:

- Check the service pricing page

- Confirm the selected Region

- Prefer free or low-cost learning activities where applicable

- Do not create resources merely for screenshots

- Stop or delete resources after the lab when they are no longer required

- Remember that some attached resources may continue generating charges even when a compute instance is stopped

- Never assume a service is free without checking current pricing and account eligibility
